## Goal

Run the exact pipeline the app uses, from a terminal, without Electron. This is how the pipeline is
built, debugged and evaluated (by you and by the AI agent) before any UI exists.

## Usage

```bash
npm run clip -- <video> --lang bn|en|hi [options]
npm run clip -- --project <id> [options]

  --projects-dir <dir>      default: apps/electron/.projects (git-ignored)
  --project <id>            reuse an existing project instead of creating one
                            (--lang optional; if given it must match project.json)
  --to <stage>              stop after this stage (e.g. --to transcribe)
  --force <stage[,stage]>   rerun these stages
  --clips <n>               default 10, 1–30            ┐ new projects only: these are
  --min <sec> --max <sec>   default 20 / 60, min < max  │ project.json settings, fixed at
  --preset <id[,id]>        default youtube-shorts      ┘ creation (exit 2 with --project)
  --llm <kind>:<model>      e.g. ollama:<model-name>, anthropic:<model-id>
  --llm-url <url>           base URL for ollama / openai-compatible
  --context <tokens>        LLM context size
  --transcriber <kind>      whisper-local | openai-compatible-transcription
  --whisper-model <name>    default from the language registry
  --replay-llm <dir>        replay recorded LLM responses (deterministic runs/tests)
  --json                    machine-readable progress lines
```

## Rules

- R1. Uses `createPipeline` with the same stages as the worker; only the injected dependencies
  differ (bins from `resources/bin/win-x64` or env `CLIPPER_BIN_DIR`; face detection stubbed until
  SPEC-080 provides a CLI path).
- R1a. Paths the user types (video, `--projects-dir`, `CLIPPER_BIN_DIR`) resolve against the folder
  the command was typed in (`INIT_CWD`), not `apps/electron`, where npm runs the script.
- R2. Keys from environment / `.env.local` (SPEC-110 R9). Never printed.
- R3. Ctrl+C aborts the run signal; the CLI waits for cleanup and exits 130.
- R4. Exit codes: 0 success, 1 stage failed, 2 bad arguments or missing binaries, 130 cancelled.
  "Missing binaries" means the ones needed by the registered stages this run reaches (up to `--to`),
  checked before a project folder is created. Bad arguments include a missing video, an unknown
  `--project`, and a `--lang` that doesn't match the project.
- R5. Prints one line per progress update (`[transcribe] 42% chunk 3/7`, `[render c01] 100%`) or
  JSON lines with `--json`: one object per line on stdout, `type` is `project`, `log`, `progress`
  or `result`; the last line is the `result` (with `exitCode`).
- R6. On success prints the project folder and the exported files (render outputs recorded in the
  manifest, so stale files from older runs aren't listed). On failure or cancel prints the command
  that resumes the project.

## Acceptance criteria

M0:

- [x] `npm run clip -- fixtures/en/short.mp4 --lang en` with zero stages registered creates a
      project folder with `project.json` and an empty manifest, exit 0.
- [x] Missing `--lang` (for a new project) or an unknown language exits 2 with a helpful message
      listing bn, en, hi.
- [x] `--project <id>` reruns an existing project without creating a folder; an unknown id or a
      different `--lang` exits 2.
- [x] A registered stage that needs a missing binary exits 2 before any folder is created (R4).
- [x] A failing stage exits 1 with the resume command; a cancel exits 130 after the stage has
      stopped (R3).
- [x] `--json` prints only JSON lines on stdout, ending with the result (R5).

M1:

- [ ] Full run on each language fixture exports clips.
- [ ] `--to transcribe` then a full run reuses the transcript (no second transcription).
- [ ] `--replay-llm` gives identical `candidates.json` across runs.

## Implementation notes

M0, no new dependencies:

- `scripts/clip.ts` only touches the process: it loads `.env.local`, parses, wires Ctrl+C and
  exits. The logic is `runClip(args, { appDir, cwd, env, signal, reporter, createPipeline? })` in
  `scripts/cli/run.ts`, which returns the exit code; tests inject fake stages via `createPipeline`.
- `createPipeline` now also returns `stages` (the registered stage names), so callers can check
  what a run needs before starting it.
- **Binaries (R4):** `binsForStage` in `run.ts` maps ingest → ffmpeg + ffprobe, transcribe →
  whisper-cli (only with `--transcriber whisper-local`), render → ffmpeg. With zero stages nothing
  is required, so M0 runs with no binaries installed. **When a stage starts spawning another
  binary, add it there.**
- **R2:** `apps/electron/.env.local` is loaded with `process.loadEnvFile`; real environment
  variables win. It can also hold `CLIPPER_BIN_DIR`. Reading the keys themselves is SPEC-110's job.
- **Paths (R1a):** npm runs the script from `apps/electron` and sets `INIT_CWD` to where the user
  typed, so `npm --prefix apps/electron run clip -- videos/a.mp4` from the repo root works. Without
  npm it falls back to `process.cwd()`. The default projects folder and `resources/` are relative
  to `apps/electron`, never the cwd.
- **Settings with `--project`** exit 2 instead of being ignored or rewriting `project.json`,
  because settings feed the stage hashes. If M1 evaluation needs "same transcript, different clip
  count", add an explicit option to this spec first.
- **M1 options** (`--llm`, `--llm-url`, `--context`, `--whisper-model`, `--replay-llm`) are accepted
  and produce one "ignored for now" warning. `PENDING_OPTIONS` in `args.ts` lists them; remove each
  one when its spec wires it. `--transcriber` is already validated (it decides the whisper-cli check).
- **Output:** text mode prints info and progress on stdout, warnings and errors on stderr, debug
  only with `CLIPPER_DEBUG=1`. A progress line repeating the previous one (same whole percent) is
  dropped; the runner already throttles to 4/s. The runner logs "<stage> failed: …" itself, so the
  CLI's failure result adds only the resume hint.
- **Ctrl+C (R3):** the first one aborts the signal and the CLI waits for the runner; a second one
  falls through to Node's default handler and quits at once. Tested with an aborted signal and a
  fake stage; the real SIGINT path through npm and tsx on Windows was not tested automatically.
- Unexpected errors (not a stage failure, e.g. no permission to create the folder) exit 1.
